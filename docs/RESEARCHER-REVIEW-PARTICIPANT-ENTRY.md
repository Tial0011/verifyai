# Participant Entry Page — Items for Researcher Confirmation

This page (`participant/entry.html`) implements the structure requested for
participant information, AI-experience background, and consent. Nothing
below has been decided by the developer — it's built so any of it can
change without a redesign. Please confirm:

1. **Exact participant information fields.** Full name, institution,
   clinical year, age, sex, and participant ID/study code are shown as
   examples from the brief. Which of these should actually be collected?

2. **Should full name be collected at all?** Given anonymity/confidentiality
   considerations, this may be better replaced by a study code only.

3. **Participant ID / study code requirements.** Entered manually by the
   participant, or generated by the system? If generated, at what point —
   on this page, or later?

4. **Which fields are required vs. optional.** Right now only the consent
   checkbox is enforced as required (per the brief). Everything else is
   marked "optional — pending confirmation." Confirm per field.

5. **Exact consent wording**, including purpose, procedures, risks/benefits,
   confidentiality, voluntary participation and withdrawal rights,
   compensation (if any), and contact information. Currently a placeholder
   block: `[RESEARCHER-APPROVED INFORMED CONSENT TEXT WILL BE INSERTED HERE]`.

6. **Eligibility criteria** — not shown on this page at all yet; confirm
   whether/how this should be communicated or checked before the form.

7. **AI-experience questions to include.** Confirm which of the eight
   example categories (exposure, frequency, clinical use, formal training,
   preferred tools, self-rated literacy, trust, comfort verifying AI
   output) should be asked, and their exact wording.

8. **Exact answer options for baseline questions**, e.g. the AI-frequency
   dropdown options and the 1–5 scale labels, are currently illustrative
   placeholders and marked `[OPTIONS TO BE CONFIRMED BY RESEARCH TEAM]`.

9. **Privacy / data-use wording** for this specific page (separate from the
   consent text) — not yet included anywhere.

10. **Study duration / instructions** specific to this stage — not yet
    included.

11. **What should happen after clicking Continue.** No destination exists
    yet (randomization and clinical cases are future phases). The button
    currently validates the form and shows an in-page message rather than
    navigating anywhere. This also needs a decision on:
    - Whether a participant record should be created in Firebase at this
      stage, or only later.
    - What data (if any) needs to persist between this page and the next,
      and where it should live in the meantime (session state vs. Firestore).

## What was deliberately not built

- No Firebase reads or writes anywhere on this page.
- No randomization, group assignment, or references to study arms.
- No clinical case content.
- No authentication.

## Notes on how this is built, for easy revision

- All required-field logic lives in one place:
  `REQUIRED_FIELD_IDS` at the top of `js/participant/entry.js`. Adding or
  removing a required field is a one-line change there — no other code
  needs to change.
- Every field that isn't yet confirmed as required/optional is visibly
  tagged in the UI ("Optional — pending confirmation") rather than
  silently assumed.
- Answer options for dropdowns/scales are isolated in the HTML markup for
  each field, so option lists can be edited or replaced without touching
  layout or validation code.
